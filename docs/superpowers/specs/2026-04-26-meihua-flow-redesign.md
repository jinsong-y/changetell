# 梅花易数流程式解卦改造设计

## 背景

当前应用已能通过时间起卦生成本卦、互卦、变卦和动爻，也能展示三卦卡片与 AI 解读。但结果页与后端输出更偏“三卦解释 + 卜辞/爻辞”，不符合用户提出的梅花易数主轴：解卦应以“体用生克”为核心，三卦用于说明事物的开始、过程、结果。

本次改造优先追求传统准确性，同时保持现有暗色、卡片、卦象条、分段解释和动效风格一致。

## 目标

1. 结果页按梅花易数完整流程展示：排三卦、分体用、论五行生克、看时令与外应、综合断语。
2. 后端确定性计算体卦、用卦、五行、生克关系和基础吉凶，不让 AI 自由编造核心吉凶。
3. 保留现有 UI 视觉语言，不做大幅视觉重做。
4. 外应不让用户输入，避免用户不理解；结果页明确说明“未取外应，以体用五行为主”。

## 非目标

1. 不新增外应输入项。
2. 不以复杂爻辞作为主判断依据。
3. 不改起卦入口的核心交互。
4. 不引入新的占筮方法或多套解卦流派选择。

## 用户体验

结果页使用流程式结构：

1. 状态栏：展示起卦时间、起卦公式、动爻。
2. 排出三卦：本卦代表开始/当前，互卦代表中间过程/隐情，变卦代表最终趋势。
3. 分辨体用：动爻所在经卦为用卦，动爻不在的经卦为体卦；体卦代表求测者/主方，用卦代表事情/客方。
4. 五行生克：展示体用五行与关系，并给出核心吉凶。
5. 时令与外应：展示体卦五行是否得令；外应固定为未取，不参与判断。
6. 综合断语：围绕用户问题给出建议，文案强调“以体用生克为主，不重复杂爻辞”。

## 数据模型

后端返回结构在现有字段基础上新增确定性字段：

```ts
interface TrigramRole {
  name: string;
  position: 'upper' | 'lower';
  element: '金' | '木' | '水' | '火' | '土';
  role: '体' | '用';
  description: string;
}

interface RelationAnalysis {
  relation: '用生体' | '比和' | '体克用' | '体生用' | '用克体';
  status: '大吉' | '小吉' | '不利' | '大凶';
  summary: string;
}

interface SeasonalAnalysis {
  bodyElement: string;
  season: string;
  strength: '旺' | '相' | '休' | '囚';
  summary: string;
}

interface OmensAnalysis {
  used: false;
  summary: string;
}
```

AI 返回字段围绕这些确定性数据扩展：

```ts
{
  "timeAnalysis": string,
  "mainHex": { "name": string, "meaning": string },
  "mutualHex": { "name": string, "meaning": string },
  "changedHex": { "name": string, "meaning": string },
  "bodyUseAnalysis": string,
  "fiveElementAnalysis": string,
  "seasonalAnalysis": string,
  "omenAnalysis": string,
  "meaning": string,
  "advice": string,
  "overallStatus": string
}
```

其中 `bodyUseAnalysis`、`fiveElementAnalysis`、`seasonalAnalysis`、`omenAnalysis` 必须受本地确定性字段约束。

## 规则设计

八卦五行：

```ts
乾兑为金，坤艮为土，震巽为木，坎为水，离为火
```

体用判定：

```ts
movingLine <= 3 => 动爻在下卦，下卦为用，上卦为体
movingLine >= 4 => 动爻在上卦，上卦为用，下卦为体
```

生克判定：

```ts
用生体 => 大吉
比和 => 大吉
体克用 => 小吉
体生用 => 不利
用克体 => 大凶
```

五行生克：

```ts
木生火，火生土，土生金，金生水，水生木
木克土，土克水，水克火，火克金，金克木
```

时令旺衰：

春木旺，夏火旺，长夏/四季土旺，秋金旺，冬水旺。先用农历月份做简化判断，输出为辅助因素，不覆盖体用生克主判断。

外应：

本次不采集外应。结果页展示“未取外应，以体用五行为主”，AI 不得编造声音、景象、人物等灵应。

## UI 改造

保留 ResultView 的现有视觉风格：

1. 暗色底、细边框、分段卡片、悬停边框色变化。
2. 三卦大卦象组件继续复用 `BigHexagram`。
3. 新增体用卡片：左右两列展示体卦与用卦，包含经卦名、上/下位置、五行、代表含义。
4. 新增生克核心卡片：突出关系、吉凶、短结论。
5. 新增时令外应卡片：两列展示旺衰与外应状态。
6. 原“爻辞卜辞解析”卡片移除或降级，不再位于核心流程。

## 后端改造

`api/chat.ts` 继续负责起卦和 AI 调用，但新增本地规则计算：

1. 计算本卦、互卦、变卦、动爻后，推导体卦与用卦。
2. 根据八卦映射计算体用五行。
3. 根据五行生克表计算关系与基础吉凶。
4. 根据农历月份给出时令旺衰辅助判断。
5. 将确定性结果注入 AI prompt，要求 AI 严格基于这些字段输出 JSON。

## 测试计划

1. 增加或提取纯函数后，用固定时间样例验证本卦、互卦、变卦、动爻、体用、生克字段。
2. 验证 `movingLine` 1-3 时下卦为用、上卦为体；4-6 时上卦为用、下卦为体。
3. 验证五行关系覆盖五类：用生体、比和、体克用、体生用、用克体。
4. 运行 `npm run build` 确认类型与前端构建通过。
5. 本地打开页面检查结果页无文字溢出，移动端卡片按单列排列。

## 开放问题

无。用户已确认选择流程式 C 方案，并要求传统准确性优先、保持现有 UI 风格一致；外应不让用户输入。
